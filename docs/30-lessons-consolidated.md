## 6. 조용히 실패하는 명령
| 날짜 | 사례 |
|---|---|
| 09-19 | `docker exec`(‑i 없이) 에 stdin 파이프 → producer 가 아무것도 안 보내고 정상 종료 |
| 09-19 | MySQL CLI 기본 문자셋으로 한글 INSERT → 깨진 채 CDC 로 ClickHouse 까지 |
| 09-19 | `docker compose up` 이 `depends_on airflow-init` 때문에 재생성 없이 종료(코드 1) |
**규칙**: "됐다"는 출력이 아니라 **하류에서 값이 보일 때** 말한다(토픽 오프셋, 테이블 행, 로그 WARN). 파이프·문자셋·의존성은 첫 실행에서 하류를 확인한다.

## 7. 판단 정정 (실수는 아니지만 바뀐 것)
- "브로커 3대는 의미 있다" → 장애 경로 확인 1회 뒤엔 형식(docs/24). "격리·보안은 비용 때문에 안 한다" → 위협 모델로 재판단, LAN 노출 실측(docs/29 §5). "리밸런스 실측하자" → Flink 정적 할당이라 철회(docs/29). "도구가 created_at 창을 읽는다" → 이미 upbit_timestamp 였음(docs/28 A-8).
**규칙**: 정정은 원문을 지우지 않고 아래에 "정정:"으로 덧붙인다. 정정 과정이 판단력의 증거다.
