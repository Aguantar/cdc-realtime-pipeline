# 29. Kafka 사용 방식 냉정 평가 — 메시지 키·처리 스타일·컨슈머·계약 (2026-09-19)

사용자 질문: "메시지 큐·이벤트 브로커·처리 스타일·컨슈머가 도메인·DE 관점에서 적절한가, 손봐야 하나." 실측(09-19 01:50)으로 답한다.

## 1. 지금 상태 (실측)
| 항목 | 값 |
|---|---|
| 체결 토픽 | 3파티션, **키 = `{"trade_id":…}`**(Debezium 기본 PK), JSON(스키마 없음, `schemas.enable=false`), **압축 없음**(Connect 기본), 보존 = **bytes 4GB/파티션**(시간 기준 없음), 12.4M 메시지 9.97GB = **약 800B/건** |
| 호가 토픽 | 6파티션, 키 = market(수집기), zstd(producer), 보존 24h·6GB |
| 처리 | 체결: 원본 싱크 + **처리 시간** 5분 창 집계 + keyed 탐지기(분 종가 = 처리 시간 타이머). 호가: **이벤트 시간** 1분 창(워터마크 5s, idleness 30s). 같은 잡군 안에서 시간 기준이 갈린다 |
| 컨슈머 | Flink 3잡(체크포인트 커밋), ClickHouse Kafka 엔진 3표(circuit). DLQ 없음. 파싱 실패는 `LOG.warn` 만(카운터·DLQ 없음) |
| 계약 | JSON, 스키마 레지스트리 없음, 하류 dbt 테스트가 유일한 방어 |
| 관측 | 브로커 JMX exporter 없음(docs/23: CLI 오염 사건), lag 은 체크포인트 톱니 |
| 보안·격리 | PLAINTEXT, ACL 없음, 타 프로젝트 2개 동거(쿼터 없음) |

## 2. 냉정한 판정
**브로커 자체는 문제가 아니다. 문제는 "메시지를 어떻게 만들고 무엇을 약속하느냐"에 있고, 그중 셋은 이미 실측 피해가 있다.**

| # | 지점 | 왜 부적절한가 (근거) | 어떻게 |
|---|---|---|---|
| 1 | **체결 키 = trade_id** | 파티션 3개에 마켓이 무작위로 흩어져 **마켓 내 순서가 깨진다**. 재정렬 5.87%/최대 4.8s(docs/20)의 원인이고, 탐지기의 "종가 정의" 버그(docs/22 §4-4)도 여기서 왔다. 도메인 관점에서 체결의 자연 키는 마켓이다 | Debezium `message.key.columns=crypto_db.crypto_trades:market` → 같은 마켓은 같은 파티션, 순서 보장. A-1 과 같은 창(어차피 키 설정을 바꿈). 편중은 BTC 518건/분 수준이라 문제 없음 |
| 2 | **처리 시간 창(체결 5분 집계)** | 재기동·정지 뒤 따라붙는 행이 "지금" 창에 들어가 과거 5분이 왜곡된다. 호가는 이벤트 시간인데 체결만 처리 시간 — 일관성 없음 | 이벤트 시간 창 + 워터마크(호가와 동일). `trade_aggregations` 는 dbt 마트(docs/27)가 대체하고 있어 폐기도 선택지 |
| 3 | **압축 없음·bytes 보존** | 800B JSON 을 그대로 → 디스크 10GB, 재처리(docs/28 §2) 하려면 시간 기준 보존이 필요한데 bytes 라 "며칠치"를 보장 못 한다 | 토픽 `compression.type=zstd`(3~5배), `retention.ms=7d` + bytes 상한 |
| 4 | **파싱 실패 = 로그 한 줄** | 잘못된 메시지가 조용히 사라진다. 대조 DAG 가 하루 뒤 잡겠지만 원인 추적 불가 | 파싱 실패 카운터(메트릭) + DLQ 토픽(원문 보존). health_check 에 카운터 |
| 5 | **스키마 계약 없음** | 생산자가 컬럼을 바꾸면 하류가 런타임에 깨진다. A-1 이 컬럼 3개를 추가하는 첫 실전 | 최소: 버전 있는 JSON 스키마 파일 + CI 검증(생산자·파서 양쪽). 정석: 레지스트리(Avro/Protobuf) — KRaft 컷오버와 묶음 |
| 6 | JMX exporter 없음 | 브로커 지표를 CLI 로 찍다 실험을 오염(docs/23) | kafka JMX exporter → Prometheus |
| 7 | 격리·보안 | 타 세입자와 쿼터 없이 동거, PLAINTEXT | 단일 호스트에선 수용. 문서에 명시 |

**괜찮은 것**: 토픽 이름 규칙(`cdc.<db>.<table>`, `upbit.orderbook.v1` 버전), 호가 키·압축·이벤트 시간, 멱등 프로듀서, Flink 체크포인트 오프셋, at-least-once + RMT, RF/minISR 결정의 근거(docs/24).

## 3. 순서
1. **A-1 창에 같이**: 키를 market 으로(#1), 토픽 zstd·7일 보존(#3) — 설정 변경뿐, 정지 없음.
2. 다음: 파싱 실패 카운터·DLQ(#4, Flink 소폭), 체결 집계 이벤트 시간화 또는 폐기(#2).
3. 스키마 계약(#5)은 A-1 의 컬럼 추가를 첫 사례로 버전 스키마 파일부터. JMX exporter(#6) 는 짬 나는 대로.
