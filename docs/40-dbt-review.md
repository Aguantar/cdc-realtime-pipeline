## 2. 문제 — 심각도 순

### ① staging 우회: 같은 원본을 9개 모델이 **제각각** 읽는다 (가장 큼)
`stg_trades` 가 있는데 정작 쓰는 모델은 2개(`int_ohlcv_1h`·`int_ohlcv_daily`)뿐이다.
나머지 **9개 모델이 `source('raw','crypto_trades')` 를 직접** 읽고, 필터가 서로 다르다.

| 필터 | 적용한 모델 |
|---|---|
| `op = 'c'` | stg_trades, int_volume_surge_daily, int_alert_transitions_recomputed, int_reconcile_hourly, dq_ingest_daily, mart_trade_orderbook_1m |
| **없음** | dim_markets, int_fx_usdt_krw_hourly, int_venue_hourly_close |

**그리고 `op='c'` 자체가 틀렸다.** `op` 는 네 값이다.

| op | 행 수 | 정체 |
|---|---|---|
| `c` | 117,660,338 | 평상시 CDC INSERT |
| `r` | 23,100 | 2026-02-13 최초 스냅샷 |
| `backfill` | 7,288 | 2026-06-27 gap-fill |
| `d` | 3 | 초기 시험 행 삭제 |

실측으로 확인: **`r` 도 `backfill` 도 `c` 와 `trade_id` 가 단 한 건도 겹치지 않는다**(두 창 모두 중복 0).
즉 **그 행들에만 존재하는 진짜 체결**이고, `op='c'` 는 그것을 버린다.

| 날짜 | `op='c'` 만 셀 때 |
|---|---|
| 2026-06-27 | 262,971 → 255,683 (**−2.77%**) |
| 2026-02-13 | 415,615 → 392,515 (**−5.6%**) |

대조 표가 09-09 부터라 이 구멍은 지금까지 **아무 테스트에도 안 걸렸다.**
그리고 필터가 모델마다 다르니 **같은 날을 물어도 모델마다 다른 답**이 나온다 — dbt 를 쓰는 이유 자체가 무너진다.

> 올바른 술어는 `op != 'd'` 다. 그리고 그것을 **한 곳(staging)에서만** 정의해야 한다.

### ② 컬럼 설명 17/71 — 넘겨받는 쪽이 보는 건 컬럼이다
모델 설명은 27/27 인데 **컬럼 설명은 71개 중 17개**뿐이다.
분석·BI 쪽이 받는 것은 모델이 아니라 `vwap`·`taker_side`·`weighted_pct`·`min_cell_pct` 같은 **열**이다.
`docs/36` 에 지표 사전을 만들었지만 **dbt 밖**이라 `dbt docs` 와 카탈로그에 안 뜬다 — 쓰는 자리에서 안 보인다.

### ③ 입도(grain)를 밝힌 모델이 2/27
"이 표의 한 행은 무엇인가"는 조인하기 전에 반드시 알아야 한다.
오늘 `dq_repairs_daily` 에서 "한 행 = (하루, 이유)" 를 몰라 `day_utc` 단독 unique 를 걸 뻔했다.
하류는 그 실수를 훨씬 조용히, 훨씬 자주 한다(중복 조인 → 합계 뻥튀기).

### ④ 계약(contract) 미사용
dbt 1.5+ 의 `contract: enforced` 를 안 쓴다. 열 이름·타입이 바뀌어도 dbt 는 통과시킨다.
**오늘 실제로 터졌다**: `trade_date → day_kst` 변경이 대시보드 10패널을 죽였다(docs/38).
계약이 있었으면 빌드 단계에서 멈췄다.

### ⑤ `persist_docs` 꺼져 있음
설명이 ClickHouse 테이블·컬럼 주석으로 안 내려간다. BI 도구에서 컬럼을 클릭해도 설명이 없다.

### ⑥ 죽은 모델 `stg_binance_trades`
09-20 에 만들고 테스트까지 붙였는데 **하류가 없다.** Binance 소비자(`dq_binance_reconcile_daily`·`int_venue_hourly_close`)는
원본을 직접 읽는다. ①과 같은 병이고, "만든 것과 도는 것" 유형이 dbt 안에서도 반복됐다.

### ⑦ exposure 가 11개 모델을 안 덮는다
특히 `int_ohlcv_1h` 는 **이상탐지 대시보드가 쓰는데** dbt 는 소비자가 없다고 본다 → 죽은 모델로 오해해 지우면 화면이 깨진다.

### ⑧ `dbt_project.yml` 에 `dimensions`·`signals` 레이어 미선언
두 폴더는 기본 materialization 이 없어 **모델마다 config 로 버틴다.** config 없이 모델을 하나 추가하면 조용히 view 가 된다.

### ⑨ 매크로 1개 — 공통 필터가 9곳에 복붙
`FINAL` + `op` 필터 + KST 변환이 모델마다 손으로 반복된다. ①의 불일치가 생긴 물리적 이유다.

### ⑩ 증분 3개가 `now()` 기준 — 백필 불가
`dq_ingest_daily`·`dq_orderbook_gaps_daily`·`mart_trade_orderbook_1m` 이 `delete+insert`(unique_key=day_utc)로 맞게 짜였지만
창을 `now()` 로 자른다. Airflow 점검(docs/39 ①)과 **같은 뿌리**다 — 함께 고쳐야 한다.

### 4-4. 하다가 걸린 것 셋
1. **주석 안에서 매크로를 호출**해 SQL 이 깨졌다(`{{ }}` 가 개행을 만들어 마침표가 독립 줄로 떨어짐). 매크로에 `{%- -%}` 공백 제어를 넣고 주석에서는 부르지 않는다.
2. **모델들이 staging 을 우회한 진짜 이유는 게으름이 아니라 열 부족**이었다 — `source_ts`·`op`·UTC 축·최우선 호가가 없었다. 뷰라서 열을 늘려도 저장 비용이 0인데 그걸 안 하고 있었다. 필요한 열을 다 내주니 우회할 이유가 사라졌다.
3. **이름 충돌을 미리 없앴다**: staging 의 체결 기준 하루를 `day_utc` 로 두면 하류의 `toDate(source_ts) AS day_utc`(적재 기준 하루)와 겹쳐, ClickHouse 의 "별칭이 원본 열을 가린다" 함정에 들어간다(docs/34 #3 에서 한 번 당했다). → `trade_day_utc`·`trade_hour_utc` 로 명명. 이름만으로 **체결 기준인지 적재 기준인지** 구분된다.

### 4-5. 이 과정에서 새로 발견한 것 (다음 라운드)
`int_volume_surge_daily` 가 **거래대금 하루를 `toDate(source_ts)`(binlog 시각)로 자른다.**
거래대금 급등 규칙은 **체결 시각** 기준이어야 한다. 평소 지연이 초 단위라 차이가 거의 없지만,
적재 지연 36.9시간 사고(docs/08) 같은 일이 나면 거래가 엉뚱한 날에 잡힌다.
이번에는 **한 번에 한 가지만 바꾼다**는 원칙에 따라 술어만 고치고 날짜 기준은 그대로 뒀다 — 별도 항목으로 남긴다.

### 5-1. 계약이 실제로 막는지 증명했다
`mart_daily_summary` 의 `close_change_pct` 를 일부러 `close_chg_pct` 로 바꿔 빌드했다.

```
Compilation Error in model mart_daily_summary
This model has an enforced contract that failed.
| column_name | definition_type | contract_type | mismatch_reason |
```

**오늘 대시보드 10패널을 죽인 것과 정확히 같은 유형의 변경**(docs/38 §1-1)이 이제 빌드에서 멈춘다.
`mart_trade_orderbook_1m` 은 증분이라 `on_schema_change` 를 정해야 했는데 **`fail`** 로 뒀다 —
`append_new_columns` 는 '조용히 늘린다'는 뜻이라 계약의 취지에 반한다.

### 5-2. 하다가 찾은 것 넷
1. **같은 모델을 선언한 yml 이 3개 있었다**(`schema.yml`·`reconcile.yml`·`volume_surge.yml`). 내가 쓴 상세 설명이 반영되지 않아 알아챘다. 둘을 지우고 하나로 합쳤다.
2. **`reconcile.yml` 이 없어진 열을 가리키고 있었다** — 설명에 `stg_trades.trade_date` 라고 적혀 있는데 그 열은 `day_kst` 로 바뀐 지 오래다. 문서가 코드보다 오래 산 사례.
3. **옛 경고가 이미 해소된 문제를 가리키고 있었다**: `stg_trades` 설명에 "2026-02 지표는 재소비 중복 ~15.4% 포함, dedup 서브쿼리 필요"가 남아 있었다. 실측하니 2026-02-14 00~06시가 **FINAL 유무와 무관하게 127,445행 = 고유키 127,445개** — RMT 전환(docs/25)으로 이미 해결됐다. 문구를 실측으로 갱신했다.
4. **`dim_coins` 의 조건부 유일성 검사를 내가 덮어써서 깨뜨렸다.** `binance_symbol` 은 바이낸스에 없는 코인에서 **빈 문자열**이라 82건이 중복으로 잡힌다. 원래 `where: "binance_symbol != ''"` 가 있었는데 문서화하며 날렸다 → 복원하고 **빈 값의 의미를 주석으로 못 박았다.**

### 5-3. 레이어 기본값도 선언했다 (⑧)
`dimensions`·`signals` 가 `dbt_project.yml` 에 없어 모델마다 `config` 로 버티고 있었다.
config 를 빠뜨린 모델을 하나 추가하면 **조용히 view 가 된다.** 둘 다 `table` 로 못 박았다.

### 5-4. 검증
`dbt build` **110 PASS / 0 ERROR**. ClickHouse `system.columns.comment` 에 설명이 실제로 내려간 것을 확인했다.
