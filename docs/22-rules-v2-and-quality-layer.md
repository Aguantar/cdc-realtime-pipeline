# 22. 이상탐지 v2 + dbt 품질 층 — 초점을 "규칙"에서 "규칙 검증 기반"으로 (2026-09-17)

docs/19 순서 4. 사용자 질문 "처음 dbt·Airflow 는 이상탐지에 초점이 맞춰져 있었는데, 지금은 파이프라인 상태에 초점을 두기로 한 것 아닌가. 그에 맞게 구성돼 있나"에 대한 답이 이 작업이다.
답은 "반쯤 그랬다"였고(docs/18 §7), 이 작업으로 정렬했다.

## 2. PRICE_24H 설계 결정

| 결정 | 왜 | 대안 기각 |
|---|---|---|
| 출력 단위 = 등급 전이 (0→1, 1→2, 2→0 …) | 거래소 지정/해제와 같은 단위여야 1:1 대조가 된다. 체결마다 내면 임계 근처에서 하루 84건(LSK) | 체결 단위 알림 |
| 참조 = 24h 전 **분 종가**, 분 슬롯 링 1,500개, 빈 분은 직전 종가로 채움 | 참조 조회 O(1) 이어야 한다(피크 59체결/s). 체크포인트 287×1,500×8B ≈ 3.4MB | MapState 스캔(분당 1,440회 탐색) |
| 늦은 이벤트 가드 유지(적재 지연 > 60초 제외) | docs/20. 백필·gap-fill 행이 링을 오염시키지 않는다 | — |
| 24h 이력 전엔 판정 없음 → **배포 후 첫 24시간은 섀도 출력 0** | 링이 비어 있으면 참조가 없다. 상태 부트스트랩(과거 24h 종가를 시작 시 주입)은 후속 개선으로 남김 | 부트스트랩 구현(복잡도) |
| 새 연산자 uid, savepoint 복원에 `--allowNonRestoredState` | 구 탐지기 상태(lastPrice·EMA)는 보존 가치가 없다. 의도적으로 버린다고 기록 | 상태 마이그레이션 |
| `rule_version` 컬럼 | 섀도('v2-shadow')와 승격 후를 데이터로 구분. 평가 모델이 버전별로 정밀도를 낼 수 있다 | 테이블 분리 |

## 4. 승격 기준 (섀도 → v2)
`dq_rule_eval_daily` 에서 **7일 연속** 아래를 만족하면 `rule_version` 을 'v2' 로 올리고 n8n 발송에 우리 전이를 추가한다.
- PRICE_24H: 정밀도 ≥ 0.9, 재현율 ≥ 0.8 (docs/16 관찰 주간 3,220/3,221 기준으로 보수적으로 잡음), 선행 시간 중앙값 기록.
- VOLUME_24H: 정밀도 ≥ 0.75, 재현율 ≥ 0.75 (백테스트 0.79/0.80 의 ±5%p).
미달이면 규칙이 아니라 **정의 차이**(참조 시각·창·예외 조건)를 먼저 의심한다. 그것이 이 표를 매일 만드는 이유다.
